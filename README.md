# Telegram-чат · GREEN-API

Минимальный React-интерфейс для отправки и получения текстовых сообщений через GREEN-API. В тестовом задании Telegram разрешён как альтернатива MAX. Визуальная структура основана на веб-мессенджере MAX: список чатов слева, переписка и поле сообщения справа.

**Статус проверки:** локальные unit и интеграционные тесты используют мок HTTP. Реальная отправка и ответ из Telegram пока не проверены. Демо не отправляет сообщения и не имитирует доказательство работающей интеграции. Подробная матрица — [docs/VERIFICATION.md](docs/VERIFICATION.md).

## Локальный запуск

Нужен Node.js **22.12+** (либо более новая поддерживаемая LTS-версия) и npm.

```bash
npm ci
npm run dev
```

Откройте адрес из терминала, по умолчанию **http://127.0.0.1:5173**. Сервер по умолчанию доступен только с локального компьютера.

Без инстанса можно нажать **«Открыть демо»**. Это отдельный локальный режим, который не делает API-запросов. Сообщения, черновики и данные подключения пропадают при обновлении страницы или отключении.

Production-сборка:

```bash
npm run build
npm run preview
```

`dist/` — результат сборки. Проект не требует `.env`, серверных секретов или базы данных.

## Подключение GREEN-API

1. Подготовьте отдельный тестовый **Telegram-инстанс** по [официальной инструкции](https://green-api.com/telegram/docs/before-start/). Это интеграция с Telegram-аккаунтом, не Telegram Bot API. Авторизация даёт провайдеру доступ к аккаунту; изучите условия и выбирайте тестовый аккаунт осознанно.
2. Инстанс должен иметь состояние `authorized`.
3. В настройках тестового инстанса включите `incomingWebhook: "yes"`, оставьте `webhookUrl` пустым. Веб-приложение проверяет настройки, но не меняет их. Не отключайте существующую рабочую интеграцию ради теста.
4. Введите **apiUrl**, **idInstance**, **apiTokenInstance** из своего кабинета в форму приложения. `apiUrl` должен быть HTTPS-адресом поддомена `green-api.com`, без пути, порта или параметров. Адрес не зашит в код: у инстансов могут быть разные серверы.
5. Подтвердите использование отдельного тестового инстанса и подключитесь.
6. Нажмите **+**, введите международный номер получателя с кодом страны. `CheckAccount` преобразует номер в канонический `chatId`. Если номер скрыт настройками приватности Telegram, поиск может не сработать даже для существующего аккаунта.
7. Отправьте текст и попросите согласившегося на тест получателя ответить в Telegram. Ответ появится в чате, пока вкладка открыта.

Не добавляйте токены в исходники, README, скриншоты, записи экрана или отчёты. Вводите реальные данные только сами и в доверенной локальной сборке.

### Очередь уведомлений

Получение использует `ReceiveNotification` → обработку → `DeleteNotification`. Подтверждение **удаляет уведомление из очереди GREEN-API**. В том числе подтверждаются неподдерживаемые типы событий, чтобы не блокировать очередь. Поэтому нужен отдельный тестовый инстанс, одна открытая вкладка и отсутствие другого потребителя этой очереди.

История не загружается из Telegram и не сохраняется между сессиями. После обновления страницы уже подтверждённые уведомления не восстановятся в этом интерфейсе. Сообщения в самом Telegram приложение не удаляет.

## Возможности

- Ввод данных инстанса в рантайме, проверка авторизации и настроек
- Создание чата по номеру, повторное открытие существующего чата без дубликатов
- Текст до 4096 UTF-16 кодовых единиц; Enter отправляет, Shift+Enter добавляет строку
- Входящий обычный текст и текст со ссылками, безопасное отображение как текста
- Последовательный long polling, отмена при отключении, ограниченный exponential backoff
- Дедупликация сообщений; повтор ACK не добавляет сообщение второй раз. После трёх неуспешных подтверждений очередь перечитывается: потерянный ответ на успешное удаление не блокирует последующие сообщения
- Отдельная обработка окончательных статусов `failed` / `noAccount`
- Защита от повторного клика, сохранение неподтверждённого текста, отмена подключения и поиска
- Русские подписи, доступные формы, мобильный вариант со списком и перепиской на отдельных экранах
- Явно обозначенное демо без сети

**«Принято API» не означает «доставлено».** Это подтверждение постановки в очередь API. При потере ответа запрос отправки автоматически не повторяется: сообщение могло уйти. Перед ручным повтором проверьте Telegram, чтобы не создать дубликат. Если сервер прислал `failed` или `noAccount`, приложение показывает ошибку; если событие не содержит `idMessage`, ошибка отображается на уровне чата.

## Проверки

```bash
npm run check       # форматирование, ESLint, TypeScript, все Vitest-тесты, сборка
npm run test:watch  # Vitest в режиме наблюдения
```

Браузерные сценарии с подменой HTTP, без реальных учётных данных:

```bash
npx playwright install chromium
npm run test:e2e
```

Если Chromium уже установлен, можно передать его путь через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. На Linux при необходимости установите системные зависимости по официальной документации Playwright. E2E-сценарии проверяют desktop/mobile, отправку/приём/ACK, отмену подключения, ошибки, очистку сессии и отсутствие переполнения по ширине; сохраняют демо-снимки в `docs/screenshots/`.

В текущей среде запуска браузерные проверки заблокированы до выполнения сценариев: Chromium не может создать процессный сокет. Поэтому визуальная проверка, реальное мобильное поведение и управление фокусом native-dialog **не объявляются пройденными**. Скриншоты текущей реализации пока отсутствуют.

CI в GitHub Actions повторяет проверки и браузерные сценарии на стандартном `ubuntu-latest`. Используются только моки, без секретов и деплоя. Артефакты со скриншотами и тестовыми трассами хранятся один день. Наличие workflow само по себе не означает, что CI уже прошёл.

## Архитектура

```text
src/
  api/          типизированный HTTP-адаптер, парсинг, long polling, тесты
  components/   подключение, диалог нового чата, экран переписки
  hooks/        жизненный цикл сессии и асинхронные действия
  chat.ts       чистый reducer сообщений и статусов
  demo.ts       полностью локальный режим
  test/         мок HTTP и настройка тестов
  App.tsx       композиция и подключение/отключение
```

React 19, TypeScript, Vite. CSS без UI-фреймворка, иконки Lucide. Vitest + Testing Library для логики и интеграции, Playwright для браузерных сценариев. Проверки принимают поддельные тестовые данные; тестовый код не отправляет их в реальный GREEN-API.

## Безопасность и ограничения

- Токен хранится только в памяти; нет localStorage, sessionStorage, cookies, аналитики или логирования запросов
- API-провайдер получает токен согласно своему контракту в пути HTTPS-запроса. Он будет виден владельцу вкладки в сетевых инструментах браузера; браузерное приложение не может скрыть его от пользователя или расширений. Не записывайте DevTools с настоящим токеном
- Произвольные API-хосты, HTTP, дополнительные пути, параметры, userinfo и нестандартные порты отклоняются до запроса. Редиректы API запрещены. Cookies и referrer не передаются
- Внешние тексты не вставляются через HTML; сырые ошибки провайдера не выводятся и не журналируются
- Обновление/закрытие вкладки и «Отключиться» сбрасывают локальную сессию и отменяют выполняющиеся запросы. Это **не** отвязывает Telegram-аккаунт от GREEN-API; отключать провайдерскую интеграцию нужно в своём кабинете
- Проверка CORS и фактической доступности сервера выбранного инстанса входит в оставшийся live-тест. Моки этого не доказывают
- Это учебный frontend-клиент для отдельного тестового инстанса, без серверной многопользовательской авторизации, долговременной истории, файлов, групповых функций и автоответов
